## 🎁 Nuove Features in v4.0

### 1. 5-Layer Concentrica Model

```
L1: CLAUDE.md (Memory)
  └─ L2: Skills+CONTEXT+ADRs (Knowledge)
    └─ L3: Hooks (Guardrails)
      └─ L4: Subagenti (Delegation)
        └─ L5: manifest.json (Distribution)
```

**Valore**: Visualmente memorabile, comunicabile in 10 secondi.

### 2. L5 Distribution Layer

**Novità**: manifest.json per team synchronization.

```json
{
  "team": "TianYi Studio",
  "skills": ["tdd-skill", "code-review-skill", "pdf-skill"],
  "agents": ["feature-dev", "code-reviewer"],
  "hooks": ["PreToolUse.sh", "PostToolUse.sh"],
  "permissions": ["git:commit", "api:read"]
}
```

**Valore**: Un comando → onboarding istantaneo per nuovo membro.

### 3. Three Analogies

- 🍳 **Scuola di Cucina**: Direttore, Cuoco, Libretto, Ricettari, Regole, Aiutanti
- ⚽ **Squadra di Calcio**: Allenatore, Giocatori, Regolamento, Mosse, Arbitro, Ruoli
- 🎂 **Ricetta Torta**: Ingredienti (L1-L5), Timer, Aiutanti, Attrezzi

**Valore**: Qualsiasi persona (anche senza background tecnico) capisce la struttura in 5 minuti.

### 4. Zero-Jargon CONTEXT.md Templates

**v3.0**: Tecnico, assume knowledge di database/API

**v4.0**: Semplicissimo

```markdown
## User (Utente)
È una **persona** che compra robe.

Ha:
- Email (per loggarsi)
- Password
- Profilo

---

## Order (Ordine)
È una **richiesta di comprare robe**.

Ha:
- Chi l'ha fatto (quale User)
- Quando (data)
- Stato (Pending → Paid → Shipped → Delivered)

⚠️ Regola: Non può tornare indietro
```

**Valore**: Qualsiasi membro del team capisce il dominio in 2 minuti.

### 5. Visual Diagrams

**v4.0 aggiunge**:
- Concentrica 5-layer diagram
- Task execution flow (DAG)
- Parallel execution diagram
- Proof of work validation gate

**Valore**: Mostrare non spiegare.

### 6. 7 Key Principles

Non-negoziable principles che proteggono l'architettura:

1. Context by Design
2. Separation of Concerns
3. Proof First
4. Determinism at Boundaries
5. Isolation Prevents Contamination
6. Knowledge is Infrastructure
7. Fail Fast, Escalate Slow

**Valore**: Chiunque sa quando è OK rompere le regole e quando no.

### 7. Scenario Reale (Feature Pagamento)

**v4.0 aggiunge** un scenario completo day-by-day:

```
Giorno 1, Mattina
├─ PM crea issue
├─ Symphony legge
├─ Context snapshot preparato
├─ Claude Code session
├─ /grill-me, /tdd, /to-issues
└─ Subagenti in parallelo

Giorno 1, Sera
└─ Test passano, merge automatico

Giorno 2
└─ Feature live! 🚀
```

**Valore**: Capire il flusso completo in 5 minuti.
